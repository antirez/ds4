## Findings considered and rejected

- Enabling Metal 4 TensorOps on M3 Ultra: rejected. The runtime intentionally
  uses the established legacy Metal kernels on pre-M5 hardware; this is not a
  correctness blocker.
- Adding native multi-shard GGUF support in this pass: rejected as too risky for
  the immediate single-machine goal. Plan 001 disables the broken sharded route
  and uses the compatible single-file antirez artifacts.
- Treating 1M-token Q4 as a release requirement: rejected. Code-derived memory
  accounting places Q4 too close to the 512-GiB physical limit; Q2 is the 1M
  context target, while Q4 is validated at 32K, 100K, and Think Max 393216.
- CUDA, ROCm, and distributed GLM certification: deferred. The requested target
  is one M3 Ultra using Metal; existing backends must still compile where the
  touched shared code requires it.
