# Q4 attention controls

[Q4 support and validation](Q4_ATTENTION.md)

Q4 support is automatic: no environment prefix is required. These controls
select rollbacks, set memory/shape limits, report diagnostics, or require a
particular eligible implementation during testing. They do not restore the
removed experimental kernels. Set controls before starting a fresh process;
several backends cache them on first use.

A **presence** flag treats even `0` as enabled. A **value-aware** flag parses its
value; its accepted spellings are specified below. `REQUIRE` is a diagnostic
assertion: it can fail a run and must not be used as a performance preset.
SSD streaming is selected separately with `--ssd-streaming`.

Metal and ROCm value-aware booleans ignore surrounding whitespace and letter
case: `0`, `false`, `no`, and `off` are false; an empty value or any other value
is true. CUDA boolean spellings vary by control, as detailed in its table.

The reference covers runtime controls added by this Q4 port and its decode
recovery. Existing upstream backend controls retain their upstream semantics.

## ROCm

Requirements apply in the dispatcher that checks them. An eligible Q-B
transient F16 call runs before the native Q4 matmul dispatcher and can bypass
its WMMA/TILE8/TILE4 assertions. To test those Q-B paths, also set
`DS4_ROCM_DISABLE_Q4_ATTN_Q_B_TRANSIENT_F16=1`; require the intended path and
check its dispatch evidence. TILE4 remains resident-only, and a TILE4
requirement applies to its K=1024, M=32768 prefill scope.
